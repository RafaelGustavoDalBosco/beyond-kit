# @dalbosco/kit

O kit de UI da Dal Bosco Systems: azul cheio sobre a base do Conta Azul, só claro, só Nunito Sans. Fonte TypeScript e CSS, sem build: cada projeto compila com o Tailwind 4 dele. Para React 19 e Tailwind 4 (Next.js 15/16 ou Vite); projeto em React 18 ou Tailwind 3 sobe antes de adotar.

Adotam: beyond-data, dalbosco-systems (hub), beyond-metric, beyond-payments, beyond-rewards e ethos-integra. Fora: Dor3D e beyond-archflow.

## Adoção

1. **Instalar** o pacote pelo tarball da tag e os peers que faltarem:

   ```sh
   npm i https://github.com/RafaelGustavoDalBosco/beyond-kit/archive/refs/tags/v0.27.0.tar.gz
   npm i radix-ui lucide-react class-variance-authority clsx tailwind-merge
   npm i @tanstack/react-table   # se usar a Tabela
   ```

   Nunca `github:` nem `git+https:`: o npm grava `git+ssh://` no lock e o `npm ci` do CI cai sem chave SSH. O tarball grava HTTPS com `integrity` e não pede git. O bump é trocar a tag na URL.

   `import { ... } from "@dalbosco/kit"` traz o núcleo inteiro (inclusive a `Tabela`, que pede o `@tanstack/react-table`); quem não a usa importa componente a componente por `@dalbosco/kit/ui/botao`, `@dalbosco/kit/ui/modal` etc.

2. **CSS**: no `globals.css` (Next) ou `index.css` (Vite):

   ```css
   @import "tailwindcss";
   @import "@dalbosco/kit/css";
   @source "../node_modules/@dalbosco/kit/src";
   ```

   Ajuste o caminho do `@source` à pasta do CSS. Sem Google Fonts: a Nunito Sans vem no pacote (`@font-face` no `kit.css`).

3. **Avisos** (o toast, no canto superior direito): `<Avisos />` uma vez na raiz e, se a API tiver um erro próprio, a frase dele:

   ```ts
   import { Avisos, avisar, configurarAvisos } from "@dalbosco/kit";
   configurarAvisos({ fraseDoErro: (erro) => (erro instanceof ErroApi ? erro.message : "A plataforma não respondeu.") });
   avisar.sucesso("Salvo."); avisar.erro(erro);
   avisar.sucesso("3 correções rejeitadas", { acao: { rotulo: "Desfazer", aoClicar: desfazer } });
   ```

4. **Pilha de fichas** (o modal de ficha, empilhado, que mora na URL, `?ficha=produto:1001|nota:196`): o `usePilha` vem do adaptador do roteador e a moldura recebe o registro das fichas:

   ```tsx
   import { usePilha } from "@dalbosco/kit/next"; // ou /tanstack, /react-router, /url
   import { PilhaDeFichas } from "@dalbosco/kit";

   <PilhaDeFichas
     usePilha={usePilha}
     fichas={{
       produto: { rotulo: "Produto", titulo: (id) => <TituloDoProduto codigo={id} />, render: (id) => <FichaProduto codigo={id} /> },
     }}
   />
   ```

   Abrir de qualquer lugar: `usePilha().abrir({ tipo: "produto", id: "1001" })`; `abrirSo` abre do zero (uma linha de lista); `voltar`, `voltarPara(i)` e `fechar` descem a pilha, pelo histórico do navegador enquanto ele cobrir. Para restringir os tipos que a URL pode abrir: `criarUsePilha(useAdaptadorDaPilha, ["produto", "nota"] as const)`.

   A leitura rápida de uma linha é a gaveta, ao lado da lista (`ComGaveta` e `Gaveta`); a pilha dela é do app, e a simples, em memória, é o `usePilhaDaGaveta`. O exemplo está em `ficha/Gaveta.tsx`.

   No Next:
   - o pacote é fonte TypeScript: `transpilePackages: ["@dalbosco/kit"]` no `next.config`;
   - os arquivos do kit com estado ou evento já trazem `"use client"`; a moldura que monta a pilha e a paleta é client component;
   - o `useSearchParams` do adaptador pede um `<Suspense>` por volta (um só, em volta do conteúdo, da pilha e da paleta, basta).

5. **As cores**: só por token (`bg-superficie`, `text-texto-2`, `text-cobalto`...), nunca hex nem cor do Tailwind.
   - Cada significado tem o par claro/forte: `cobalto`/`cobalto-suave`, `ganho`, `aviso`, `risco`, `neutro` e `agua` (o verde-água do ICMS-ST e das entradas), cada um com o `-suave`; o `PAR_DO_TOM` dá o par pronto.
   - `linha` é a borda de cartão, caixa e campo; `fio`, a divisória entre as linhas de uma lista. `texto-2` é o secundário, sempre em peso 600 a 700, nunca apagado. `cobalto-anel` é o anel de foco do campo e o contorno do cartão sob o mouse (`risco-anel` no campo com erro).
   - `cabecalho`, `cabecalho-2`, `cabecalho-3` e `cabecalho-texto` são o azul do cabeçalho do app, a pílula translúcida, o hover dela e o texto sobre ele. O menu lateral é branco: `lateral` é o fundo, `lateral-ativo` o texto azul do item ativo, `lateral-cheio` o fundo azul claro dele, `lateral-apagado` o item sem tela, `lateral-aviso` e `lateral-ganho` o estado sobre ele.
   - `lote` é a barra de lote escura. Sobre o `BlocoDestaque`, o texto é `text-destaque-texto` e o apagado `text-destaque-texto-2`. As séries de um gráfico são `serie-1` a `serie-5`, na ordem.
   - Variantes: `celular:` (até 760px) e `mesa:` (761px para cima).
   - Raios: `rounded-controle` (10, o campo), `rounded-icone` (12, o ícone e o item de menu), `rounded-cartao` (14), `rounded-bloco` (16, a caixa), `rounded-ficha` (20, o modal de ficha) e `rounded-pilula` (20, a pílula e o botão).
   - Sombras: `shadow-1` e `shadow-bloco` são quase nenhuma (cartão, caixa, botão, campo); a forte fica só em menu e dica (`shadow-2`), modal e aviso (`shadow-3`), na gaveta (`shadow-gaveta`) e na folha do celular (`shadow-folha`).
   - Pesos da Nunito Sans: 400, 600, 700 e 800 (`font-normal`, `font-semibold`, `font-bold`, `font-extrabold`), nunca `font-medium`.

6. **A gramática**: azul é ação e seleção, verde ganho, laranja o que pede ação, vermelho risco, cinza neutro e verde-água ICMS-ST e entrada.
   - A tela abre com os cartões de número (`CartoesDeNumero` com os `Indicador`), quatro por linha; as abas são em pílula.
   - A lista é a `LinhaDeLista` dentro de um `Bloco` (a caixa), com a escolhida em azul claro e a barra azul à esquerda. A linha abre a gaveta ao lado (leitura rápida) e a ficha grande abre no modal (`PilhaDeFichas`), pela gaveta ou direto: o kit dá os dois e o app escolhe. O `MestreDetalhe` segue para a lista com o detalhe ao lado e para os itens dentro do modal de ficha (`emCaixa`).
   - Formulário e confirmação abrem em modal (`Modal`, `BotaoDeConfirmar`); o resultado de uma ação vai ao toast (`avisar`), no canto superior direito.
   - Na primeira carga, o esqueleto no formato da tela (`Carregando`); ao recarregar o que já está na tela (outra aba, outro filtro, outro mês), a barra fina no alto e a lista antiga apagada no lugar (`BarraDeCarga`, `Recarregando`); nunca um giro no meio da tela vazia.
   - Número e código levam a classe `numero`. Título é sempre em frase, em 800, nunca em caixa alta: `rotulo` (a caixa alta pequena) fica só no grupo da paleta.
   - Sem degradê e sem brilho; `filete`, `titulo-secao` e `aurora` não existem.
   - No celular (até 760px) o menu lateral dá lugar à `BarraDeNavegacao`, a gaveta vira a folha que sobe de baixo e o modal de ficha ocupa a tela.

## Componentes

- `Emblema` (`icone` ou `sigla`; `tom` cobalto, ganho, aviso, risco, neutro ou agua; `forma` circulo ou quadrado; `tamanho` xs, sm, md ou lg; `cheio`), `PAR_DO_TOM` e o tipo `TomDoEmblema`: o ícone colorido do kit, em círculo (cartão de número, estado, confirmação, aviso, notificação) ou em quadrado de raio 12 (a linha de lista, com a sigla ou o ícone da operação; o cabeçalho da ficha). `cheio` inverte o par: fundo forte, conteúdo branco.
- `Botao` (primario em azul cheio, secundario com contorno azul, fantasma só texto, neutro com contorno cinza para o Cancelar, ganho, perigo com contorno vermelho, perigo-cheio, lateral; lg de 48px, md de 38, sm de 30, icone, icone-sm; todos em pílula, os de ícone redondos; `asChild` dá o visual a um `Link` ou `<a>`; `carregando` põe o giro dentro do botão, desabilitado, e `textoCarregando` troca o texto), `Tecla` (o kbd) e `BotaoDeCopiar` (neutro por padrão; só ícone em `icone`/`icone-sm`, `avisoAoCopiar`, `onClick`).
- `CabecalhoDoApp` (`sigla`, `nome`, `hrefDaMarca`/`aoClicarNaMarca`, `contexto`, `busca`, `sino`, `hrefDaAjuda`/`aoAjudar`, `usuario` com `nome`, `papel` e `email`, `itensDoUsuario`, `aoSair`, `versao`/`hrefDaVersao`, `menuAberto`/`aoAlternarMenu`, `Link`): o cabeçalho de todo app, fixo no alto de ponta a ponta, em azul cheio, com 60px (56 no celular). Da esquerda para a direita: a marca, o `contexto` do app na pílula translúcida (a empresa com o seletor), o `BotaoDeBusca` como campo branco e, no fim, a ajuda, o `Sino` e o avatar com as iniciais, que abre o menu do usuário (o avatar, o nome e o papel no alto, os itens do app com ícone, como Minha conta, Novidades e Suporte, o Sair em vermelho e a versão no pé). No celular a busca fica só na lupa, a ajuda some e a marca mostra o `nome` inteiro; o botão da gaveta do `MenuLateral` só aparece para quem passa `aoAlternarMenu` (quem usa a `BarraDeNavegacao` não passa), e aí a marca é a `sigla`. O conteúdo recua com `RECUO_DO_CABECALHO`.
- `MenuLateral` (`itens`, `ativo`, `aberto`/`aoFechar`, `Link`): branco, com a borda à direita e só a navegação, embaixo do cabeçalho: itens de raio 12 (o ativo em azul claro com o texto azul; `contagem` no selo à direita) e grupos que abrem e fecham, um aberto por vez (o título longo quebra em linhas, nunca corta). O grupo de um filho só vira item direto, com o nome e o ícone do grupo; o item sem `href` fica à mostra, apagado e sem clique. Marca, seletor, usuário, Sair e versão moram no `CabecalhoDoApp`; a busca nunca fica no menu. No celular ele some (a navegação é a `BarraDeNavegacao`) e a gaveta só abre para quem passa `aberto`. O conteúdo recua com `RECUO_DO_MENU`.
- `BarraDeNavegacao` (`itens` com `rotulo`, `icone`, `href` ou `aoAbrir` e `ativo`; `ativo`, `Link`): a navegação do celular, presa embaixo: até cinco itens com ícone e rótulo, que o app escolhe, o ativo em azul; um deles pode abrir o resto do menu (o `aoAbrir` ligando o `aberto` do `MenuLateral`). Acima de 760px não aparece. O conteúdo recua com `RECUO_DA_BARRA`: `<main className={cn(RECUO_DO_CABECALHO, RECUO_DO_MENU, RECUO_DA_BARRA)}>`.
- `CabecaDaTela` (`titulo`, `descricao`, `acoes`, `rotulo`, `trilha`, `Link`): o alto da tela, dentro da área: o título em frase (24px, 800), a frase embaixo e as ações à direita (o seletor de mês em pílula, os botões). `trilha` (os `PassoDaTrilha`, com `rotulo` e `href` ou `aoAbrir`) é o "‹ Tela › Subtela" acima do título, para a tela que não está no menu.
- `AreaDaTela` (`largura` estreita, media ou larga; `respiro`): o conteúdo de toda tela de dentro do app fica no meio da área, com largura máxima, nunca esticado na tela toda. A casca envolve as telas na `larga`, com `respiro` (os respiros da área, menores no celular); a tela de registro ou formulário se fecha na `media` ou `estreita`.
- `BarraDoTopo`: a barra branca da tela, presa embaixo do cabeçalho (ícone, trilha, título em frase, `subtitulo`, as ações da tela como o mês e os botões, sem a busca; `carregando` liga a linha fina no pé dela, com o app dizendo quando, como o `useIsFetching` do TanStack). `useLugaresDoTopo`, `ProvedorDoTopo` e `NoTopo`: a ponte para a tela pôr a frase, as ações e o título dela na barra da casca (o exemplo está em `ui/topo.tsx`).
- `Sino` e `BotaoDeBusca`: o sino do `CabecalhoDoApp` com a contagem das não lidas (9+) e o painel das notificações (`notificacoes`, `naoLidas`, `aoAbrir`, `aoMarcarTodas`, `vazio`): o cabeçalho com "Marcar todas como lidas" e cada notificação com o ícone em círculo (`icone` e `tom` dizem o que ela é), a nova em azul claro. O `BotaoDeBusca` é o campo branco em pílula que abre a busca do Ctrl K (`aoBuscar`, com o texto de `exemplo` e o atalho à mostra; no celular, só a lupa). Os dados e a marcação de lida são do app.
- `Novidades` (`versoes`, `titulo`, `frase`, `vazio`): a tela de Novidades inteira (cabeçalho e linha do tempo das versões, a mais nova marcada em azul cheio, com as seções Novidades, Melhorias e Correções), no formato que o hub entrega; o app só formata a data.
- `CartoesDeNumero` (`compacto`) e `Indicador` (`rotulo`, `valor`, `detalhe`, `icone`, `tom`, `aoAbrir`, `href`, `asChild`, `ativo`, `realce`, `compacto`, `carregando`): a grade que abre a tela (quatro por linha; no celular, dois, com o ícone em cima) e o cartão de número: branco, com o ícone no círculo do tom, o rótulo, o valor em 800 e a linha pequena embaixo. Com `aoAbrir`, `href` ou `asChild` o cartão leva a outra tela; `ativo` marca o escolhido com a borda azul (o cartão que é seletor); `realce` pinta o fundo com o tom. `compacto` (no cartão ou no `CartoesDeNumero`) tira o ícone e aperta o respiro; dentro do `ComGaveta` ele liga sozinho com a gaveta aberta, e o `compacto` passado pelo app ganha (o contexto `IndicadorCompacto` liga o mesmo em outro lugar). `carregando` mantém o rótulo e o ícone e põe o esqueleto no valor. Nada corta: no cartão estreito o ícone sai e o valor e o detalhe quebram linha.
- `Bloco`, `CabecaDoBloco`, `Destaque`: a caixa (o bloco branco de raio 16 que agrupa uma lista ou um conteúdo; corta o que passa do canto, então o que precisa sair dela fica fora ou passa `overflow-visible`), o alto dela (`titulo` em 800, `detalhe`, `icone`, a `acaoDeTexto` em azul à direita, como "Ver todas", com `aoAbrir` ou `href`, e `acao` para o que não é texto) e o número de destaque dentro dela (`tom`, `grande`, `emCaixa`).
- `BlocoDestaque`, `SeloDoDestaque`, `LinhaDoDestaque`: o bloco em azul claro chapado, com o número que pede o olho (`aoAbrir` faz o bloco todo clicável). `FaixaDeNumeros`, `Segmento` (`detalhe`, `selos`, `tom` risco ou ganho, `apagado`, `largo`, `aoAbrir` com `ativo`) e `DivisorDaFaixa`: a faixa baixa de números, para quando a altura conta e a lista precisa começar perto do topo; não é mais o padrão de abertura de tela. Quebra em linhas quando não cabe.
- `GraficoDeBarras` (`barras` com `rotulo`, `valor`, `referencia` e `projecao` de `minimo` a `maximo`; `formatar`, `altura`, `rotuloDaProjecao`) e `LegendaDoGrafico` (`itens` com `tipo` fechado, referencia ou projecao): o gráfico de barras, sem biblioteca: os meses fechados em azul, o de referência em azul cheio com o valor em cima e a projeção como barra tracejada, com a faixa em azul claro e o traço do valor provável, separada por uma linha vertical. A legenda vai na `acao` da `CabecaDoBloco`.
- `Quadro`, `ColunaDoQuadro` (ponto da cor, contagem, legenda), `CartaoDoQuadro` (`href`, `aoAbrir`, `asChild`; `acoes` no pé, fora do clique): o quadro por situação (até 5 colunas).
- `Selo` (neutro, cobalto, ganho, aviso, risco, agua e o contorno tracejado; `tamanho` md ou sm, o da linha de lista; `contorno` troca o fundo pelo branco com borda, com o texto na cor do tom; `comPonto`) e o tipo `Tom`.
- `Dica` (o (?)) e `TermoComDica` (o termo sublinhado, para cabeçalho de tabela e texto corrido): explicam um termo no balão escuro, que abre com o mouse em cima e fica aberto com o clique ou o toque. `conteudo` em texto puro é o balão curto; `{ titulo, texto, exemplo }` é o completo. `Rotulado` e `Par` têm a prop `dica`. Só nos termos difíceis, com os textos num glossário único do app (`dica={GLOSSARIO.mva}`), nunca soltos nas telas.
- `Abas`, `TrilhoDeAbas`, `Aba` (`icone`, `contagem`), `ConteudoDaAba`: as abas, em pílula: a ativa em azul cheio, as outras em cinza claro e a contagem dentro do texto; no celular o trilho rola de lado. `largo` ocupa a largura toda e reparte entre as abas; `sublinhado` é a variante de abas de texto sobre um fio, a ativa em azul com o traço embaixo. O anel de foco aparece só pelo teclado, nunca depois do clique. Aceitam "" como valor (o filtro "Todos").
- `LinhaDeLista` (`icone` ou `sigla` com `tom`, `titulo`, `apoio`, `colunas`, `valor` com `tomDoValor`, `selo`, `larguras`, `escolhida`, `aoAbrir`/`href`/`asChild`, `selecionada`/`aoSelecionar`) e `ListaDeLinhas`: a linha de uma lista, alta, dentro de um `Bloco`: o quadrado colorido da sigla (ICMS, ST, PIS, NCM) ou da operação, o título em 700 com a linha de apoio, as colunas curtas, o valor em 800 e o selo. A escolhida fica em azul claro, com a barra azul à esquerda; `aoSelecionar` põe a caixa de seleção do lote. No celular as colunas curtas somem e o valor e o selo se empilham à direita.
- `BarraDeFiltros` (`abas`, `etiquetas`), `Filtros` (`ativos`, `aoAplicar`, `aoLimpar`, `aberto`/`aoMudarAberto`), `GrupoDeFiltros`, `EtiquetaDeFiltro` (`rotulo`, `aoTirar`) e `Ordenacao` (`opcoes`, `valor`, `aoMudar`): os filtros de uma lista. As abas e a busca fazem o recorte principal; o botão "Filtros", com a contagem dos ativos, abre o painel (os grupos, Limpar, Cancelar e Aplicar); o filtro aplicado vira etiqueta azul clara com ×; a ordenação é um menu. O que está marcado, o rascunho do painel e o que vale depois do Aplicar são do app (o exemplo está em `ui/filtros.tsx`).
- `BarraDeLote` (`contagem`, `total`, `aoLimpar`) e `AcaoDoLote`: a barra escura que flutua embaixo da lista enquanto há linha marcada, com a contagem, o total, as ações e o × que limpa a seleção. Vai depois do `Bloco` da lista, fora dele (a caixa corta o que passa do canto). A ação principal é um `Botao` primário `sm`; a secundária, a `AcaoDoLote`.
- `Paginacao` (`page`, `page_size`, `total`, `aoMudar`, `tamanhos`/`aoMudarTamanho`, `compacta`): a paginação no pé da caixa: "1–25 de 342", as páginas em círculo, com a atual em azul cheio, e o "Por página". Some quando tudo cabe numa página; no celular, só a atual entre as setas.
- `MestreDetalhe`, `ItemDaLista`, `GrupoDaLista`, `PaginasDaLista`, `CarregarMais`: a lista à esquerda e o detalhe do escolhido à direita. Solto na tela, cada item é um cartão (o escolhido em azul claro, com a barra azul) e o detalhe vem numa caixa; empilha abaixo de `lg`. `emCaixa` é o master/detail de dentro de um `Bloco` (o do modal de ficha): a lista em linhas separadas pelo fio e o detalhe ao lado; empilha no celular. `titulo` e `contagem` fazem a cabeça padrão da lista, com a busca e os filtros na `cabeca` embaixo; `largura` é a da lista (360px); `GrupoDaLista` é o título de grupo entre os itens, com o valor à direita; `PaginasDaLista` é a `Paginacao` compacta; `CarregarMais` é o pé da lista que vem aos pedaços, com `emBloco` no pé de um bloco; `embutido` tira a caixa do detalhe, para o detalhe que monta as caixas dele; `ItemDaLista` com `href` ou `asChild` vira link e `em="linha"` põe ícone, texto e seta lado a lado.
- `Tabela` (TanStack Table; `meta.numero` alinha à direita, `meta.principal` fica com a sobra, `meta.quebra` deixa o texto em várias linhas, `meta.fixa` prende a coluna à esquerda, `meta.centro` centraliza, `meta.esconderAbaixo` some abaixo de sm/md/lg; `aoAbrir` faz a linha inteira clicável e `podeAbrir` limita quais; `escolhida` marca a linha aberta ao lado, em azul claro com a barra azul; `expandir` abre uma linha de detalhe embaixo; `atributosDaLinha` põe data-*/aria-* no `<tr>`; `idDaLinha` mantém as linhas abertas quando os dados mudam; `vazio` aceita ReactNode; `classeDaLinha`, `grupo` para a faixa de título e o `footer` das colunas no rodapé; com `pagina` e `aoMudarPagina` a `Paginacao` vai no pé, e `tamanhosDaPagina` com `aoMudarTamanhoDaPagina` ligam o "Por página"; `densa` é a tabela curta dentro de uma ficha: linhas de 40px, cabeçalho de 36px e o `SemValor` como um ponto) e o tipo `Pagina`.
- `Campo` (42px, raio 10, anel azul no foco; `icone` à esquerda quando ajuda a ler, e aí a classe de posição vai num elemento de fora; `tamanho="lg"` é o de 48px do login), `Busca`, `CampoDeSenha` (com o olho), `Rotulado` (o rótulo em cima, em 700, liga ao controle do kit por id, sem envolvê-lo; `ajuda` embaixo; `erro` pinta a borda do controle de vermelho e põe a frase com ícone; `obrigatorio`, `opcional`, `dica`, `acao`; controle nativo dentro dele leva `htmlFor` e o mesmo `id`), `AreaDeTexto`, `Escolha` (`vazio` troca ou tira a opção vazia; `children` para `optgroup`), `EscolhaSegmentada` (`opcoes`, `valor`, `aoMudar`, `name`: a escolha curta entre poucas opções lado a lado), `SimNao` (em escolha segmentada, com o contrato do select: `value` "true", "false" ou vazio e o `onChange` com `e.target.value`; o clique no segmento já marcado volta ao vazio, menos com `required`), `Caixa`, `Alternativa` (o radio; `variante="cartao"` é a escolha em cartões com explicação, com `titulo` e `descricao`): os controles de formulário; `GradeDoFormulario` (2 a 8 colunas, de 5 para cima só no `xl`; o `Rotulado` estende com `ocupa`) e `SecaoDoFormulario` (o grupo com o título em frase sobre um fio, `icone` opcional); `CampoMoeda` (o R$ fixo, formata ao sair e no Enter, vazio é null; `comoTexto` para dinheiro em string decimal).

## O que não está no kit

O seletor de mês, as fichas da plataforma (produto, nota, fornecedor), os rótulos do `/rotulos`, o cliente da API e os erros dele (`ErroApi`, `ErroRede`): isso é de cada projeto, montado em cima do kit.

## Mudar o kit

- Uma linha de versão só: o projeto sempre sobe para a tag mais nova, nunca para um patch de versão antiga. Antes do bump, `gh release list -R RafaelGustavoDalBosco/beyond-kit` e o Release de cada tag desde a sua dizem o que muda para quem usa.
- Quem edita o kit é a sessão do kit ou a do hub (dalbosco-systems). A sessão de outro projeto nunca edita o kit: o que falta ela escreve no próprio projeto, no padrão do kit, e registra como candidato (ou como problema do kit) no ticket aberto do projeto **KIT** no hub (`ticket.py abertos KIT`), não no ticket do próprio projeto. Uma sessão só do kit lê esse ticket, junta os candidatos e solta a versão.
- Toda tag sai com o Release no GitHub: o que muda para quem usa e o comando do bump.
- Antes de cada tag: `npm i` e `npm run tipos` (o TypeScript mais novo dos projetos e o 5.7); a tag só sai com os dois limpos.
- Versão: o que só acrescenta sobe o patch ou o minor; o que muda a tela de quem já usa (como o `MestreDetalhe` empilhar no celular) sobe o minor e vai dito no commit, para os projetos saberem no bump.
