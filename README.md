# @dalbosco/kit

O kit de UI da Dal Bosco Systems, no desenho Lastro: Onest, tons calmos, azul só para interação, tema claro e escuro, com o claro como padrão. Fonte TypeScript e CSS, sem build: cada projeto compila com o Tailwind 4 dele. Para React 19 e Tailwind 4 (Next.js 15/16 ou Vite); projeto em React 18 ou Tailwind 3 sobe antes de adotar.

Adotam: dalbosco-systems (hub), beyond-payments, beyond-rewards e ethos-integra. Fora: Dor3D, beyond-archflow, beyond-data e beyond-metric.

O Beyond Data tem o Lastro próprio, no repositório dele.

## Adoção

1. **Instalar** o pacote pelo tarball da tag e os peers que faltarem:

   ```sh
   npm i https://github.com/RafaelGustavoDalBosco/beyond-kit/archive/refs/tags/v1.0.0.tar.gz
   npm i radix-ui lucide-react clsx tailwind-merge
   npm i @tanstack/react-table   # se usar a Tabela
   ```

   Nunca `github:` nem `git+https:`: o npm grava `git+ssh://` no lock e o `npm ci` do CI cai sem chave SSH. O tarball grava HTTPS com `integrity` e não pede git. O bump é trocar a tag na URL.

   `import { ... } from "@dalbosco/kit"` traz o núcleo inteiro (inclusive a `Tabela`, que pede o `@tanstack/react-table`); quem não a usa importa componente a componente por `@dalbosco/kit/ui/botao`, `@dalbosco/kit/ui/modal` etc.

2. **CSS**: no `globals.css` (Next) ou `index.css` (Vite):

   ```css
   @import "tailwindcss";
   @import "@dalbosco/kit/css";
   @source "../node_modules/@dalbosco/kit/src";
   ```

   Ajuste o caminho do `@source` à pasta do CSS. Sem Google Fonts: a Onest vem no pacote (`src/fontes`, com o `OFL.txt`), pelo `@font-face` do `tokens.css`.

3. **Tema antes de pintar**: o `SCRIPT_DO_TEMA` aplica a escolha salva antes do primeiro quadro; sem escolha salva, fica o claro (nunca o tema do sistema).

   ```tsx
   // app/layout.tsx (Next): o arquivo não é "use client", então o layout de servidor lê o texto
   import { SCRIPT_DO_TEMA } from "@dalbosco/kit/script-do-tema";

   <html lang="pt-BR" suppressHydrationWarning>
     <head>
       <script dangerouslySetInnerHTML={{ __html: SCRIPT_DO_TEMA }} />
     </head>
   ```

   No Vite, o mesmo texto vai no `<head>` do `index.html`; quando a CSP bloqueia script inline, num arquivo do `public` (`<script src="/tema.js">`).

4. **Avisos e hint**, uma vez na raiz: `<Avisos />` (o toast, no rodapé, centrado) e `<CamadaDeHint />` (a janelinha escura que abre em qualquer elemento com `data-hint`, e `data-hint-titulo` e `data-hint-atalho` se quiser). Se a API tiver um erro próprio, a frase dele:

   ```ts
   import { Avisos, CamadaDeHint, avisar, configurarAvisos } from "@dalbosco/kit";
   configurarAvisos({ fraseDoErro: (erro) => (erro instanceof ErroApi ? erro.message : "A plataforma não respondeu.") });
   avisar.sucesso("Salvo."); avisar.erro(erro);
   avisar.sucesso("3 itens rejeitados", { acao: { rotulo: "Desfazer", aoClicar: desfazer } });
   ```

   ```tsx
   <button data-hint="Exporta a lista filtrada" data-hint-titulo="Exportar" data-hint-atalho="Ctrl E">…</button>
   ```

5. **Pilha de fichas** (os painéis empilhados à direita, com as lombadas das anteriores; a pilha mora na URL, `?ficha=produto:1001|pedido:196`): o `usePilha` vem do adaptador do roteador e a moldura recebe o registro das fichas:

   ```tsx
   import { usePilha } from "@dalbosco/kit/next"; // ou /tanstack, /react-router, /url
   import { PilhaDeFichas } from "@dalbosco/kit";

   <PilhaDeFichas
     usePilha={usePilha}
     fichas={{
       produto: { rotulo: "Produto", titulo: (id) => <TituloDoProduto codigo={id} />, render: (id) => <FichaProduto codigo={id} /> },
     }}
   />
   ```

   Abrir de qualquer lugar: `usePilha().abrir({ tipo: "produto", id: "1001" })`; `abrirSo` abre do zero (uma linha de lista); `voltar`, `voltarPara(i)` e `fechar` descem a pilha, pelo histórico do navegador enquanto ele cobrir. Para restringir os tipos que a URL pode abrir: `criarUsePilha(useAdaptadorDaPilha, ["produto", "pedido"] as const)`.

   A leitura rápida de uma linha é a gaveta, ao lado da lista (`ComGaveta` e `Gaveta`); a pilha dela é do app, e a simples, em memória, é o `usePilhaDaGaveta`. O exemplo está em `ficha/Gaveta.tsx`.

   No Next:
   - o pacote é fonte TypeScript: `transpilePackages: ["@dalbosco/kit"]` no `next.config`;
   - os arquivos do kit com estado ou evento já trazem `"use client"`; a moldura que monta a pilha e a paleta é client component;
   - o `useSearchParams` do adaptador pede um `<Suspense>` por volta (um só, em volta do conteúdo, da pilha e da paleta, basta).

## As cores e as medidas

Só por token, nunca hex: o `kit.css` zera as paletas, os tamanhos de fonte, os pesos, os raios e as sombras padrão do Tailwind, e só os do Lastro existem como utilitário. O espaçamento (passo de 4px) e os pontos `sm`/`md`/`lg`/`xl` continuam os do Tailwind.

- **Superfícies**: `fundo` (o chão), `mesa` (a lateral, o recuado), `ficha` (cabeçalho, painel, cartão), `campo` (campo e botão secundário), `sub` (a trilha, o cabeçalho de tabela dentro de painel), `busca`, `hover`.
- **Texto e borda**: `texto`, `texto-secundario`, `texto-apoio`, `texto-inverso`; `borda`, `borda-suave` (o fio entre linhas), `borda-forte`; a rampa `neutro-200` a `neutro-900`.
- **Ação**: `acao`, `acao-texto` (link e texto de ação), `acao-sobre` (texto sobre o azul), `acao-100`, `acao-200`, `acao-300`, `acao-400`, `acao-700`, `acao-800`.
- **Sentido**: `positivo` (entrou, deu certo, ganho), `destaque` (o segundo realce, que não é ação), `atencao` (vencido, atrasado, pede olho), cada um com o `-fundo`; `positivo-sobre-escuro`; `erro` e `erro-fundo`, só para falha de sistema; `ok` (o ponto de conectado e o toast de sucesso).
- **Estados de um registro**, sempre com o sinal: `estado-aberto` ○, `estado-marcado` ◔, `estado-andamento` →, `estado-aplicado` ◑, `estado-concluido` ● (o único cheio), `estado-erro` ✕, `estado-cancelado` (riscado), `estado-conferir` ?; os seis primeiros com o `-fundo`. O `Selo estado="..."` já desenha.
- **Séries** de gráfico, legenda e ponto de aba: `serie-1` a `serie-5`, na ordem.
- **Escuros**: `hint`, `hint-titulo`, `hint-texto` (o hint, a barra de lote, o painel do login); `veu` e `veu-painel`; `painel`, `painel-2`, `painel-3`, `painel-linha`, `painel-texto`, `painel-texto-2`, `painel-texto-3`, `painel-destaque` (o painel de TV, sempre escuro); `brasao-ouro`.
- **Fonte**: `text-micro` (11), `text-apoio` (12), `text-base` (13), `text-base-celular` (14), `text-enfase` (15), `text-botao-celular` (16), `text-subtitulo` (18), `text-titulo` (20), `text-numero-p` (24), `text-numero-m` (28), `text-numero-g` (34), `text-numero-xg` (54). Pesos: `font-normal` (400), `font-medio` (500), `font-forte` (600). `leading-texto`, `leading-titulo`, `leading-numero` e `tracking-titulo`.
- **Raios**: `rounded-p` (4: selo, caixa de seleção, tecla), `rounded-m` (7: botão, campo), `rounded-g` (10: painel, cartão, modal), `rounded-pilula` (filtros).
- **Sombras**: `shadow-p` (cartão, item ativo), `shadow-m` (painel de detalhe), `shadow-g` (modal, flutuante, toast), `shadow-topo` (cabeçalho), `shadow-acao` (botão principal).
- **Variantes**: `celular:` (abaixo de 640px) e `mesa:` (640px para cima). Animações: `animate-entrar`, `animate-subir`, `animate-deslizar`, `animate-folha`, `animate-surgir`, `animate-correr`. Utilitários: `numero` (algarismos tabulares; o `body` já liga) e `sem-barra`.

O tema escuro é só a troca das variáveis sob `<html data-tema="escuro">`: nenhuma classe `dark:`, e nenhum componente sabe qual tema está ativo. O produto pode trocar a família `--acao*` (a cor por produto; no portal do Beyond Rewards, a loja também); os outros tokens são fixos.

## A gramática do Lastro

- Azul só para interação: link, botão, seleção, foco. Nenhum dado é azul: número e barra de gráfico ficam na tinta do texto, dos neutros, das séries ou dos tons de sentido.
- Estado é sinal mais texto, nunca só cor (o `Selo estado`, os sinais ○ ◔ → ◑ ● ✕ ?). O sentido também leva sinal: as classes `.positivo`, `.destaque` e `.atencao` do CSS põem ↓, + e ◇ antes do valor.
- Estimativa: `.estimativa`, com o ≈, em itálico e com o pontilhado embaixo (no gráfico, a barra pontilhada). Sem dado: `SemValor` ("sem dado", em itálico), nunca zero nem travessão.
- Números tabulares e à direita (`numero`, `meta.numero` na `Tabela`). Títulos em frase, peso 600, nunca em caixa alta: a caixa alta pequena fica no cabeçalho da tabela e no grupo da paleta.
- O detalhe de uma linha abre ao lado da lista (a `Gaveta`, ou o `MestreDetalhe`); para ir mais fundo, a pilha de fichas. Formulário e confirmação abrem em modal (`Modal`, `BotaoDeConfirmar`); o resultado de uma ação vai ao toast (`avisar`), no rodapé.
- Carregamento: na primeira carga, o esqueleto no formato da tela (`Carregando`); ao recarregar o que já está na tela (outra aba, outro filtro, outro mês), a barra fina e a lista antiga apagada no lugar (`BarraDeCarga`, `Recarregando`); nunca um giro no meio da tela vazia.
- A casca: o `CabecalhoDoApp` claro de 56px, fixo de ponta a ponta; o `MenuLateral` de 200px embaixo dele (gaveta até 960px); a trilha de 36px (`BarraDoTopo`) presa sob o cabeçalho; no celular (abaixo de 640px), a `BarraDeNavegacao` embaixo, a gaveta vira a folha que sobe de baixo e o modal ocupa a tela. O conteúdo recua com `<main className={cn(RECUO_DO_CABECALHO, RECUO_DO_MENU, RECUO_DA_BARRA)}>`.
- Regra de domínio não é do kit: o que é fiscal ("nada se soma", a fonte do número, "sem vencimento") mora no Beyond Data. A particularidade de cada produto (qual estado é "Vencida", "Baixa confiança") o projeto monta sobre os tokens do kit; candidato ao kit só se servir a mais de um produto.

## Componentes

Marcado como *sem efeito*: a prop continua aceita (o código antigo compila), mas não muda nada.

- `Botao` (`tipo`: primario, o azul cheio, um por área; secundario e neutro, o branco com contorno cinza, o neutro para o Cancelar; fantasma, só o texto azul; positivo e perigo-cheio, cheios; perigo, o contorno vermelho, para o que apaga ou rejeita; lateral, o item discreto. `tamanho`: lg de 48px (celular e login), md de 32, sm de 28, icone de 32 e icone-sm de 28; só o ícone em fantasma, neutro ou lateral é o `.btn-icon` cinza, sem contorno. `asChild` dá o visual a um `Link` ou `<a>`; `carregando` põe o giro e desabilita, `textoCarregando` troca o texto; desabilitado, guarda o `title` no hover) e os tipos `TipoDoBotao` e `TamanhoDoBotao`. `Tecla` (o kbd). `BotaoDeCopiar` (`valor`, `rotulo`, `copiado`, `avisoAoCopiar`, `onClick`; neutro por padrão; só o ícone em `icone`/`icone-sm`; copiado, o ✓ no verde de ok).
- `BotaoDoTema` (a lua no claro, o sol no escuro; já vem no `CabecalhoDoApp`), `useTema` (`"claro"` ou `"escuro"`), `alternarTema` (troca e salva neste navegador), `iniciarTema` (aplica a escolha salva) e o tipo `Tema`.
- `CamadaDeHint`: o hint, montado uma vez na raiz. Abre depois de 400 ms com o mouse parado ou com o foco pelo teclado (o foco pelo clique não abre); fecha ao sair, ao rolar ou com Esc; abre embaixo e sobe se não couber; nunca recebe clique. No celular abre ao tocar no elemento que não é link nem botão. `HintEstatico` é o hint parado, para a vitrine.
- `Emblema` (`icone` ou `sigla`; `tom` neutro, acao, positivo, destaque, atencao, erro ou andamento; `tamanho` xs, sm, md ou lg; `cheio`; `forma` *sem efeito*), `PAR_DO_TOM` e o tipo `TomDoEmblema`: o quadrado de raio 7 no fundo recuado, com o ícone ou a sigla no traço do tom; `cheio` pinta o quadrado no par claro/forte do tom.
- `Selo` (`tom`: os de `TomDoEmblema` e `contorno`, o pontilhado; `estado`: aberto, marcado, andamento, aplicado, concluido, erro, cancelado ou conferir, com o sinal antes do texto, e aí o `tom` fica de fora; `tamanho` md ou sm, o da linha de lista; `contorno` troca o fundo pelo do campo com borda, o texto na cor do tom; `comPonto`; `title`) e os tipos `Tom` e `EstadoDoSelo`.
- `CabecalhoDoApp` (`sigla`, `nome`, `hrefDaMarca`/`aoClicarNaMarca`, `contexto`, `busca`, `sino`, `hrefDaAjuda`/`aoAjudar`, `usuario` com `nome`, `papel` e `email`, `itensDoUsuario` com `rotulo`, `icone`, `href` ou `aoClicar` e `contagem`, `aoSair`, `versao`/`hrefDaVersao`, `menuAberto`/`aoAlternarMenu`, `Link`): o cabeçalho claro, fixo, de 56px. Da esquerda para a direita: o ☰ da gaveta (até 960px, só para quem passa `aoAlternarMenu`), a marca (o quadrado azul com a sigla e o nome), o `contexto` (texto solto em negrito, ou o seletor do app), a busca, o sino, o tema, a ajuda e o usuário (as iniciais, o nome e o papel), que abre o menu: o e-mail no alto, os itens do app e, no pé, a versão e o Sair. Ao estreitar nada rola de lado: o nome do usuário e a tecla da busca somem até 1180px, o nome do produto até 960px, o texto da busca e o tema no celular. `RECUO_DO_CABECALHO`, `ALTURA_DO_CABECALHO`, `useNoCabecalho` e os tipos `ItemDoUsuario` e `PropsDoCabecalho`.
- `MenuLateral` (`itens`, `ativo`, `aberto`/`aoFechar`, `pe`, `Link`): só a navegação, em texto, no fundo de mesa com a borda à direita, sob o cabeçalho. O item ativo vai na ficha, em azul, com a sombra pequena; a `contagem`, à direita. Os grupos abrem e fecham, um aberto por vez, e o do item ativo abre sozinho; o grupo de um filho só vira item direto, com o nome do grupo; o item sem `href` fica apagado e sem clique. `pe` é a linha de situação no pé, com o ponto verde. Até 960px vira gaveta, aberta só por `aberto`; o Esc e o véu fecham. `icone` dos itens *sem efeito*. `RECUO_DO_MENU`, `LARGURA_DO_MENU` e os tipos `ItemDoMenu`, `LinkDoMenu` e `PropsDoMenuLateral`.
- `BarraDeNavegacao` (`itens` com `rotulo`, `href` ou `aoAbrir` e `ativo`; `ativo`, `Link`, `className`): a navegação do celular, presa embaixo, só em texto: até cinco itens em partes iguais, o ativo em azul com o fio em cima; um deles pode abrir o resto do menu (o `aoAbrir` ligando o `aberto` do `MenuLateral`). De 640px para cima não aparece. `icone` *sem efeito*. `RECUO_DA_BARRA`, `ALTURA_DA_BARRA`.
- `BarraDoTopo` (`trilha`, `titulo`, `subtitulo`, `acoes`, `carregando`, `voltaUmPasso`): a trilha de 36px presa sob o cabeçalho, com os passos até a tela (Comercial / Clientes), o `titulo` como passo atual, a frase ao lado (some no celular) e as ações à direita. `voltaUmPasso` liga o Alt ← (o `history.back()`) e a dica dele; `carregando` corre a barra fina no pé (o app diz quando, como o `useIsFetching` do TanStack). `icone` *sem efeito*. `useLugaresDoTopo`, `ProvedorDoTopo` e `NoTopo` (`titulo`, `frase`, `acoes`): a ponte para a tela pôr a frase, as ações e o título dela na barra da casca (o exemplo está em `ui/topo.tsx`).
- `CabecaDaTela` (`rotulo`, `titulo`, `descricao`, `acoes`, `trilha` com os `PassoDaTrilha`, `Link`): o alto da tela, dentro da área: o título em frase (20px, 600; 18 no celular), a frase embaixo e as ações à direita; `trilha` é o "Tela / Subtela" acima do título, para a tela que não está no menu.
- `AreaDaTela` (`largura` estreita, media ou larga; `respiro`): o conteúdo no meio da área, com largura máxima, nunca esticado. A casca envolve as telas na `larga` com `respiro`; a tela de formulário ou registro se fecha na `media` ou `estreita`.
- `Sino` (`notificacoes`, `naoLidas`, `aoAbrir`, `aoMarcarTodas`, `vazio`) e o tipo `Notificacao` (`id`, `titulo`, `texto`, `quando`, `lida`, `icone`; `tom` *sem efeito*): o sino com o ponto vermelho enquanto há não lido e o flutuante dos avisos, com "Não lidos" e "Todos" no alto, o não lido em azul claro e "Marcar todos como lidos" no pé. `BotaoDeBusca` (`aoBuscar`, `exemplo`): o campo de busca do cabeçalho, que abre a paleta, com a tecla (Ctrl K, ⌘ K no Mac). Os dados e a marcação de lida são do app.
- `Novidades` (`versoes`, `titulo`, `frase`, `vazio`) e o tipo `VersaoDasNovidades`: a tela de Novidades inteira, a linha do tempo discreta (a versão mais nova com o ponto azul), com as seções Novidades, Melhorias e Correções, no formato que o hub entrega; o app só formata a data.
- `CartoesDeNumero` (`compacto`) e `Indicador` (`rotulo`, `valor`, `detalhe`, `icone`, `tom`, `aoAbrir`, `href`, `asChild`, `ativo`, `realce`, `compacto`, `carregando`): a grade que abre a tela (até quatro por linha; dois no celular) e o cartão de número: o rótulo de apoio com o ícone pequeno e neutro, o valor em 500 e a nota embaixo. O `tom` positivo, destaque, atencao ou erro põe o filete de 2px no alto; `realce` pinta o fundo claro do tom; `ativo` marca o escolhido com a borda azul; com `aoAbrir`, `href` ou `asChild`, o cartão leva a outra tela. `compacto` tira o ícone e aperta; dentro do `ComGaveta` liga sozinho com a gaveta aberta (o contexto `IndicadorCompacto` liga em outro lugar). `carregando` põe o esqueleto no valor.
- `Bloco` (a caixa: ficha com borda, raio 10 e sombra leve; corta o que passa do canto, então o que precisa sair dela fica fora ou passa `overflow-visible`), `CabecaDoBloco` (`titulo`, `detalhe`, `icone` pequeno e neutro, `acaoDeTexto` no fantasma com `aoAbrir` ou `href`, `acao` para o que não é texto) e `Destaque` (`rotulo`, `valor`, `selo`, `detalhe`, `tom` texto, positivo, destaque, atencao ou erro, só no valor; `grande`; `emCaixa`).
- `BlocoDestaque` (`rotulo`, `valor`, `selo`, `aoAbrir`): a caixa do número grande, neutra (o Lastro não tem bloco de cor); com `aoAbrir` a caixa toda é clicável e os links de dentro seguem por cima. `SeloDoDestaque` (o selo pontilhado, como a estimativa) e `LinhaDoDestaque` (`rotulo`, `valor`, `fatia`, o filete da fatia em tinta neutra). `FaixaDeNumeros`, `Segmento` (`rotulo`, `valor`, `detalhe`, `selos`, `tom` erro ou positivo, `apagado`, `largo`, `aoAbrir` com `ativo`) e `DivisorDaFaixa`: a faixa baixa de números, para quando a altura conta; não é o padrão de abertura de tela.
- `GraficoDeBarras` (`barras` com `rotulo`, `valor`, `referencia` e `projecao` de `minimo` a `maximo`; `formatar`, `altura`, `rotuloDaProjecao`) e `LegendaDoGrafico` (`itens` com `tipo` fechado, referencia ou projecao): o gráfico de barras sem biblioteca, em tinta neutra (nenhuma barra é azul): os fechados no `neutro-400`, a referência no `neutro-800` com o valor em cima e a projeção como estimativa, no contorno pontilhado, com a faixa na mesa e o traço do valor provável, depois de uma linha vertical pontilhada. A legenda vai na `acao` da `CabecaDoBloco`.
- `Quadro` (`colunas` 2 a 5), `ColunaDoQuadro` (`titulo`, `tom` do ponto, `contagem`, `legenda`) e `CartaoDoQuadro` (`href`, `aoAbrir`, `asChild`; `acoes` no pé, fora do clique): o quadro por situação, as colunas na mesa e os cartões de ficha dentro.
- `Dica` (o (?)) e `TermoComDica` (o termo sublinhado, para cabeçalho de tabela e texto corrido): o balão escuro do hint, que abre com o mouse em cima e fica aberto com o clique ou o toque. `conteudo` em texto é o balão curto; `{ titulo, texto, exemplo }` é o completo; o tipo `ConteudoDaDica`. `Rotulado` e `Par` têm a prop `dica`. Só nos termos difíceis, com os textos num glossário único do app, nunca soltos nas telas.
- `Abas`, `TrilhoDeAbas` (`largo`, `aria-label`; `sublinhado` *sem efeito*), `Aba` (`icone`, `contagem`) e `ConteudoDaAba`: as abas sublinhadas sobre o fio, a ativa em azul escuro com o traço de 2px e peso 600, a contagem dentro do texto ("Pendentes 12"); no celular o trilho rola de lado. `largo` é o segmentado da largura toda. O anel de foco aparece só pelo teclado. Aceitam "" como valor (o filtro "Todos").
- `LinhaDeLista` (`icone` ou `sigla`, `titulo`, `apoio`, `colunas`, `valor` com `tomDoValor`, `selo`, `larguras`, `escolhida`, `aoAbrir`/`href`/`asChild`, `selecionada`/`aoSelecionar`/`rotuloDaSelecao`; `tom` *sem efeito*) e `ListaDeLinhas`: a linha de uma lista dentro de um `Bloco`, como a linha da tabela: o marcador pequeno e neutro, o título em 600 com a linha de apoio, as colunas curtas, o valor tabular à direita (o `acao` fica na cor do texto) e o selo. ## O que não está no kit

O seletor de mês, as fichas da plataforma (produto, nota, fornecedor), os rótulos do `/rotulos`, o cliente da API e os erros dele (`ErroApi`, `ErroRede`): isso é de cada projeto, montado em cima do kit.

## Mudar o kit

- Uma linha de versão só: o projeto sempre sobe para a tag mais nova, nunca para um patch de versão antiga. Antes do bump, `gh release list -R RafaelGustavoDalBosco/beyond-kit` e o Release de cada tag desde a sua dizem o que muda para quem usa.
- Quem edita o kit é a sessão do kit ou a do hub (dalbosco-systems). A sessão de outro projeto nunca edita o kit: o que falta ela escreve no próprio projeto, no padrão do kit, e registra como candidato (ou como problema do kit) no ticket aberto do projeto **KIT** no hub (`ticket.py abertos KIT`), não no ticket do próprio projeto. Uma sessão só do kit lê esse ticket, junta os candidatos e solta a versão.
- As decisões do desenho Lastro moram no `CLAUDE.md` do kit. O `tokens.css` tem os valores da entrega do Lastro com os nomes genéricos; quando o Lastro mudar, a atualização passa pela tabela de nomes do `CLAUDE.md`, nunca por cópia da entrega.
- Do 0.x para o 1.0: `python <kit>/scripts/migrar-para-1.0.py frontend/src`, de dentro do projeto, uma vez só por projeto (rodar de novo troca o `text-base` já migrado). Ele troca cor, tamanho de fonte, peso, raio, sombra e os valores de `tom`; no fim lista as classes que sobraram sem par. O que muda de desenho fica para a revisão.
- Toda tag sai com o Release no GitHub: o que muda para quem usa e o comando do bump.
- Antes de cada tag: `npm i` e `npm run tipos` (o TypeScript mais novo dos projetos e o 5.7); a tag só sai com os dois limpos.
- Versão: o que só acrescenta sobe o patch ou o minor; o que muda a tela de quem já usa (como o `MestreDetalhe` empilhar no celular) sobe o minor e vai dito no commit, para os projetos saberem no bump; a troca do desenho inteiro sobe a versão maior.
